## 0. پیش تیاری (ایک بار)

- [ ] دو الگ الگ Supabase اکاؤنٹس (A اور B) بنا لیں یا استعمال میں لائیں — Pillar E کی رازداری کی جانچ کے لیے لازمی۔
- [ ] ہر تین فلیگز فعال ہونے چاہئیں (Lovable کے env / `.env` میں): `VITE_PERSONAL_CORPUS`, `VITE_KNOWLEDGE_GRAPH`, `VITE_RECIPES` — اور `VITE_ANNOTATIONS` بھی (M4.0 کا annotations فیچر)۔
- [ ] ٹیسٹ اکاؤنٹ میں کافی ٹوکن بیلنس یقینی بنائیں (چنکڈ رنز اور ingest ٹوکن خرچ کریں گے)۔
- [ ] ایک نمونہ PDF (اگر 300 صفحات کا میسر نہ ہو تو کم از کم 30–50 صفحات کا متنی، غیر سکینڈ PDF) اور ایک ~60,000 حرفی اردو دستاویز تیار رکھیں۔

## 1. M4.0 — بقایا و استحکام

### 1.1 `summarize_sections` (باب وار خلاصہ)
- [ ] ایک document کھولیں جس میں 2+ عنوانات (headings) ہوں۔
- [ ] Slash menu (`/`) یا Task Library سے **"ابواب و عناوین کا خلاصہ (Summarize Sections)"** چلائیں۔
- [ ] **متوقع:** ہر عنوان/باب کا اپنا الگ خلاصہ بنے (پوری دستاویز کا ایک ہی خلاصہ نہیں)۔
- [ ] عام `summarize` ("خلاصہ بنائیں") صرف منتخب متن پر چلتا رہے — بغیر انتخاب کے بلاک ہو۔

### 1.2 Reload کے بعد رن کا Resume
- [ ] ~60,000 حرفی دستاویز پر کوئی chunked ٹاسک (مثلاً "حرکات لگائیں") چلائیں۔
- [ ] رن جاری ہوتے ہوئے (batch 3-4 پر) صفحہ **reload** کریں۔
- [ ] **متوقع:** Canvas کے نیچے ایمبر رنگ کا کارڈ آئے — عبارت: *"نامکمل رن: {task} (X از Y مکمل)"* — دو بٹن: **"باقی ماندہ پر جاری رکھیں"** اور **"چھوڑ دیں"**۔
- [ ] "باقی ماندہ پر جاری رکھیں" دبائیں → باقی batches مکمل ہوں۔
- [ ] الگ ٹیسٹ: رن کے دوران دستاویز میں تھوڑا متن تبدیل/ٹائپ کر دیں، پھر reload کریں → **"باقی ماندہ پر جاری رکھیں"** بٹن ظاہر ہی نہ ہو (صرف "چھوڑ دیں")۔

### 1.3 حاشیہ نوٹس (Annotations)
- [ ] متن منتخب کر کے نوٹ لگائیں (Annotation sheet سے)۔
- [ ] اسی متن کے حصے پر کوئی chunked AI رن چلائیں جو اسے بدل دے۔
- [ ] **متوقع:** نوٹ حذف نہیں ہوتا — Annotation فہرست میں **"منقطع نوٹ (متن تبدیل ہو گیا)"** کے طور پر اپنے اصل اقتباس کے ساتھ رہے۔

### 1.4 کوڈ کوالٹی (خودکار طور پر تصدیق شدہ — دوبارہ چیک کی ضرورت نہیں)
- [x] `RichEditor.tsx` (297 سطور) اور `EditorToolbar.tsx` (292 سطور) دونوں 300 سطور کی حد کے اندر ہیں۔ *(کوڈ آڈٹ سے تصدیق شدہ 2026-07-30)*

## 2. Pillar E — ذاتی کتب خانہ (Personal Library / RAG)

نیویگیشن: Library ستون (بائیں) → **"Sources"** ٹیب۔

### 2.1 اپلوڈ اور Ingest
- [ ] Sources ٹیب سے "+ Upload" پر نمونہ PDF منتخب کریں۔
- [ ] اپلوڈ ڈائلاگ میں **تخمینی chunks** اور ٹوکن بیلنس نظر آئیں (اگر بیلنس ناکافی ہو تو "ٹوکن ناکافی ہیں" پیغام آئے اور اپلوڈ بٹن غیرفعال رہے)۔
- [ ] اپلوڈ کی تصدیق کریں → toast: *"فائل محفوظ ہو گئی۔ پس منظر میں کتب خانے کا پروسیس شروع ہے…"*
- [ ] Ingest کارڈ پر پیش رفت % نظر آئے (IngestProgressCard)۔
- [ ] بیچ کے دوران **"منسوخ"** بٹن دبائیں۔
- [ ] **متوقع:** کارڈ پر *"منسوخ — N حصے محفوظ ہیں"* آئے؛ اب تک کے chunks ضائع نہ ہوں (item حالت `failed` نہیں بلکہ صاف طور پر نامکمل)۔
- [ ] دوبارہ ایک چھوٹی فائل مکمل ingest ہونے دیں → toast: *"کتب خانے میں کتاب کا پروسیس مکمل ہو گیا!"*

### 2.2 تلاش اور حوالہ
- [ ] Workbench کے Research ٹیب میں مأخذ سوئچ میں **"میری کتابیں"** (یا مماثل) آپشن موجود ہو۔
- [ ] اسی اپلوڈ شدہ کتاب کے کسی موضوع پر **"علمی حوالہ جات تلاش کریں"** (citations) چلائیں۔
- [ ] **متوقع:** Source card پر بیج **"میرا کتب خانہ"** + کتاب کا عنوان + مقام آئے، کوئی جعلی/عوامی URL نہ ہو۔
- [ ] `VITE_PERSONAL_CORPUS=false` کر کے (اگر ممکن ہو ٹیسٹ ماحول میں) دوبارہ citations چلائیں → نتائج بعینہٖ ویسے ہی ہوں جیسے فلیگ آن ہونے سے پہلے (کوئی regression نہیں)۔

### 2.3 رازداری — دو اکاؤنٹس کا فیصلہ کن ٹیسٹ ⚠️ (سب سے اہم)
- [ ] اکاؤنٹ **A** سے ایک منفرد/خاص موضوع والی کتاب اپلوڈ کر کے ingest مکمل ہونے دیں۔
- [ ] لاگ آؤٹ کر کے اکاؤنٹ **B** سے لاگ اِن کریں۔
- [ ] اکاؤنٹ B سے اسی موضوع پر citations/Research چلائیں۔
- [ ] **متوقع:** اکاؤنٹ A کا کوئی chunk، عنوان، یا اقتباس اکاؤنٹ B کے نتائج میں **ہرگز** ظاہر نہ ہو۔
- [ ] Sources ٹیب میں بھی B کو صرف اپنی (اگر کوئی ہوں) کتابیں نظر آئیں، A کی نہیں۔

### 2.4 حذف کی سالمیت
- [ ] Sources ٹیب سے ایک library item حذف کریں۔
- [ ] **متوقع:** اس کتاب پر مبنی citations اب نہ آئیں (chunks حذف)۔ *(Storage فائل کا حذف ہونا بیک اینڈ سے ہے — اگر Supabase dashboard تک رسائی ہو تو `library-files` bucket میں بھی فائل غائب ہونی چاہیے۔)*

### 2.5 OCR/Transcribe پل
- [ ] `/ocr` یا `/transcribe` پر ایک نتیجہ مکمل کریں۔
- [ ] **"کتب خانے میں محفوظ کریں"** بٹن دبائیں (SaveToLibraryButton)۔
- [ ] **متوقع:** یہ آئٹم Sources ٹیب میں ظاہر ہو اور ingest pipeline سے گزرے۔

## 3. Pillar F — Knowledge Graph / Entities

نیویگیشن: Library ستون → **"Graph"** ٹیب (صرف `VITE_KNOWLEDGE_GRAPH=true` پر نظر آئے گا)۔

### 3.1 استخراج
- [ ] ایک علمی مضمون (اشخاص/کتب کے ناموں والا) کھول کر Graph ٹیب میں **"گراف نکالیں"** بٹن دبائیں۔
- [ ] **متوقع:** toast *"N ہستیاں اور M روابط شامل کیے گئے"*؛ فہرست میں اشخاص، کتب، اصطلاحات الگ الگ اقسام میں نظر آئیں۔
- [ ] دستاویز کا متن کھول کر چیک کریں — **ایک حرف بھی تبدیل نہ ہوا ہو**۔

### 3.2 Entity Card اور Backlinks
- [ ] کسی entity پر کلک کریں → کارڈ میں نام (اردو+عربی اگر موجود ہو)، قسم، خلاصہ، اور **"علمی روابط"** نظر آئیں۔
- [ ] backlink (متعلقہ دستاویز) پر کلک کریں → Canvas میں وہی دستاویز کھلے، صفحہ دوبارہ لوڈ کیے بغیر۔

### 3.3 Duplicate Detection (خودکار ضم ممنوع)
- [ ] «ابن تیمیہ» اور «ابن تیمیۃ» (یا ملتے جلتے دو نام) والی دستاویزات/کتب پر استخراج چلائیں۔
- [ ] **متوقع:** اوپر **"ممکنہ ڈپلیکیٹ (N)"** کی تجویز آئے — دو entities خود بخود ضم **نہ** ہوں۔
- [ ] صارف خود ضم کا بٹن دبائے → toast: *"'X' کو 'Y' میں ضم کر دیا گیا"* → پرانا نام `aliases` میں محفوظ رہے (الگ کرنا ممکن رہے)۔

### 3.4 فلیگ آف ریگریشن
- [ ] `VITE_KNOWLEDGE_GRAPH=false` پر Library ستون میں صرف **Docs | Sources** ٹیبز رہیں (Graph غائب)، باقی ایپ ویسی ہی چلے۔

## 4. Pillar G — Recipes

نیویگیشن: Library ستون → **"Recipes"** ٹیب (صرف `VITE_RECIPES=true` پر)۔

### 4.1 `polish_document`
- [ ] ایک document کھلا ہونا چاہیے (Canvas میں)، ورنہ toast: *"دستاویز ایڈیٹر میں کھلی نہیں — پہلے Canvas میں دستاویز کھولیں۔"*
- [ ] Recipes ٹیب سے **polish_document** منتخب کریں۔
- [ ] **متوقع:** ایک ہی pre-flight ڈائلاگ (**"ٹوکن کی لاگت اور رن کی تصدیق"**) میں تمام قدموں کے **کل** Batches اور ٹوکن دکھیں (تین الگ ڈائیلاگ نہیں)۔
- [ ] تصدیق سے پہلے کوئی network request نہ جائے (Network ٹیب میں چیک کیا جا سکتا ہے)۔
- [ ] تصدیق کے بعد تینوں قدم **ترتیب وار** چلیں (normalize_script → spelling_check → auto_format)۔

### 4.2 Fail-stop
- [ ] (اگر ممکن ہو) کسی قدم کو جان بوجھ کر ناکام کروائیں (مثلاً بیچ میں انٹرنیٹ منقطع کریں یا بیلنس ختم کر دیں)۔
- [ ] **متوقع:** اگلا قدم شروع نہ ہو؛ کارڈ پر "قدم 2 از 3 پر رکا" جیسی واضح حالت دکھے؛ پہلے قدم کا کام محفوظ رہے۔

### 4.3 Undo
- [ ] Recipe مکمل ہونے کے بعد Trust ٹیب یا TaskRunCard پر **"پورا رن واپس لیں"** بٹن دبائیں۔
- [ ] **متوقع:** دستاویز بالکل Recipe چلنے سے پہلے کی حالت میں واپس آ جائے۔

### 4.4 429 سے پاک
- [ ] 40+ batches کا کوئی طویل Recipe/chunked رن چلائیں (یا `cite_and_summarize` بڑی دستاویز پر)۔
- [ ] **متوقع:** ایک بھی HTTP 429 نہ آئے (throttle خود بخود 2.4s فی بیچ رکھے)۔

### 4.5 AI Review کے ساتھ تصادم
- [ ] Track Changes (AI Review) آن کر کے کوئی Recipe چلانے کی کوشش کریں۔
- [ ] **متوقع:** صاف پیغام کے ساتھ رن **شروع ہی نہ ہو**۔

### 4.6 Trust ٹیب گروپنگ
- [ ] Recipe مکمل ہونے کے بعد Workbench کے **Trust** ٹیب میں جائیں۔
- [ ] **متوقع:** Recipe ایک **قابلِ کھلنے والے گروپ** کی صورت میں دکھے (تین بکھری غیرمتعلق قطاریں نہیں)۔

## 5. موبائل / RTL / رسائی (360px)

براؤزر DevTools میں 360px چوڑائی پر (یا حقیقی موبائل پر) جانچیں:

- [ ] Sources ٹیب کا اپلوڈ ڈائلاگ درست RTL میں کھلتا اور بند ہوتا ہے۔
- [ ] Ingest کارڈ (پیش رفت % + منسوخ بٹن) 360px پر پڑھنے کے قابل ہے۔
- [ ] Graph ٹیب کا Entity کارڈ اور "ممکنہ ڈپلیکیٹ" سیکشن نہیں ٹوٹتا۔
- [ ] Recipe کا pre-flight ڈائلاگ (SolvencyDialog) 360px پر مکمل نظر آتا ہے، بٹن نہیں کٹتے۔
- [ ] Library ستون کے چار ٹیبز (Docs/Sources/Graph/Recipes) موبائل پر Sheet کی صورت قابلِ استعمال ہیں۔
