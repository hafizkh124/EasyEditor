# M7 P0 اسپائیک — رن بک

یہ فولڈر `docs/SPEC-M7.md` کے منصوبے (پلان فائل `wiggly-toasting-otter.md`)
کے **P0 مرحلے** کے چھ ثبوت خودکار کرتا ہے۔ یہ سکرپٹس ایک **اصل ونڈوز مشین**
پر چلائے جائیں جس میں **Microsoft Word اور InPage نصب ہوں** — یہ Claude Code
کا یہ (Linux) سیشن اُنہیں خود نہیں چلا سکتا، اِس لیے یہ صرف کوڈ ہے، نتیجہ نہیں۔

> **کیوں یہ لازم ہے:** پلان صراحتاً کہتا ہے — "کوئی [ثبوت] ناکام ہو تو معماری
> اُسی وقت بدلے، P1 پر نہیں"۔ اگر یہ ثبوت یہاں غائب رہیں اور P1 (ورڈ اڈاپٹر
> کا اصل کوڈ) شروع ہو جائے، تو پوری تہہ ۱/۲ ایک ایسی مفروضے پر کھڑی ہوگی جو
> کبھی جانچی نہیں گئی۔

## ضروریات

- ونڈوز ۱۰/۱۱، Microsoft Word (کوئی بھی حالیہ ورژن) نصب
- Node.js 18+ (`node --version`)
- InPage نصب (Part A/B کے لیے؛ نہ ہو تو بھی باقی پانچ ثبوت چلائے جا سکتے ہیں —
  مگر اُس کا مطلب ہے InPage کا حصہ الگ سے حل طلب رہے گا)
- **اختیاری، آپ کی اپنی لائسنس شدہ فونٹ فائل** (مثلاً Jameel Noori Nastaleeq
  کی `.ttf`) — یہ فولڈر کوئی فونٹ فراہم نہیں کرتا، لائسنسنگ کی وجہ سے۔
- LibreOffice نصب (ثبوت ۳ کے لیے؛ اگر نہ ہو تو یہی نتیجہ ہے کہ "detect" ناکام
  رہے گا — یہی بتانا مقصود ہے)
- ایک نمونہ `.docx` جس میں چند پیراگراف اردو/نستعلیق متن ہو (کسی حقیقی مقالے
  کا ایک صفحہ کافی ہے)
- ایک نمونہ متنی (نہ کہ اسکین شدہ) `.pdf` (اختیاری، ثبوت ۲ کے لیے)

## چلانے کا طریقہ

```powershell
cd p0-spike

# ثبوت ۱، ۲، ۶ — ورڈ COM، PDF Reflow، یتیم process
node run-all.mjs "C:\path\to\sample.docx" "C:\path\to\sample.pdf"

# ثبوت ۳ — LibreOffice کی موجودگی اور تبدیلی
node test-libreoffice.mjs "C:\path\to\sample.docx"

# ثبوت ۵ — فی صارف فونٹ کی تنصیب
# پہلے word-bridge.ps1 کو الگ ونڈو میں چلائیں اور اُس میں ایک docx کھولیں:
powershell -NoProfile -ExecutionPolicy Bypass -File word-bridge.ps1
#   {"op":"open","path":"C:\\path\\to\\sample.docx"}
# پھر ایک دوسری ونڈو میں:
powershell -NoProfile -ExecutionPolicy Bypass -File font-install-test.ps1 -FontPath "C:\path\to\YourFont.ttf"
# اسکرپٹ جو JSON کمانڈ دکھائے، وہ پہلی ونڈو میں پیسٹ کریں اور "found" دیکھیں۔
```

**ثبوت ۴ (ان پیج ↔ RTF)** خودکار نہیں ہو سکتا — `inpage-rtf-checklist.md`
کھولیں اور دستی طور پر مکمل کریں۔ یہی اُس کا اصل سبب ہے کہ ان پیج کا کوئی
عوامی API نہیں ملا۔

## نتیجہ کیسے واپس بھیجیں

ہر سکرپٹ کا مکمل ٹرمینل آؤٹ پٹ (PASS/FAIL سمیت) اور
`inpage-rtf-checklist.md` کے مکمل شدہ چیک باکسز واپس بھیج دیں۔ چھ میں سے
کوئی بھی ناکام ہو تو یہ نہ سمجھیں کہ اُسے "بعد میں ٹھیک کر لیں گے" — پلان کے
مطابق یہی وہ لمحہ ہے جہاں متعلقہ حصے کی معماری پر دوبارہ غور ہونا ہے:

| ثبوت ناکام ہو | پلان کا کون سا حصہ متاثر |
|---|---|
| ۱ (ورڈ COM) | پوری تہہ ۱/۲ — بنیادی مفروضہ ہی غلط |
| ۲ (PDF Reflow) | تہہ ۳ کا "PDF (متن) → ورڈ" راستہ؛ OCR راستے پر مکمل انحصار کرنا پڑے گا |
| ۳ (LibreOffice) | "عالمگیر متبادل" کا دعویٰ؛ Office-کے-بغیر صارف کے لیے کوئی راستہ نہیں رہے گا |
| ۴ (ان پیج RTF) | پوری InPage حکمتِ عملی؛ UI automation یا InPage سپورٹ ترک کرنے پر نظرثانی |
| ۵ (فونٹ) | سلامتی کے دروازے کی مَد ۴؛ شاید ورڈ کو دوبارہ چلانا لازمی قرار دینا پڑے |
| ۶ (یتیم process) | تہہ ۱ کے `process.ts` کی ڈیزائن تفصیلات — خطرہ اصلی نکلا تو صفائی کا طریقہ ابھی سے سخت کرنا ہوگا |

## اِس فولڈر کے بعد کیا ہو

یہ فولڈر خود P1 کا حصہ نہیں — یہ صرف ثبوت ہے۔ P0 پاس ہونے کے بعد:
- `word-bridge.ps1` کا پیٹرن `electron/host/powershell.ts` میں دوبارہ (نہ کہ
  اِسی فائل کو) لکھا جائے گا، مناسب error handling اور IPC کے ساتھ۔
- یہ پورا فولڈر حذف کیا جا سکتا ہے، یا `docs/adr/` میں ثبوت کے طور پر ریکارڈ
  رکھنے کے لیے محفوظ — فیصلہ آپ کا۔
